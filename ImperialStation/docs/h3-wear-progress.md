## Behavior

`MachineFault` disturbances and configured wear events exhaust the current installed
cartridge through an explicit, resource-accounted sink. An empty slot consumes
nothing; repeated faults still count as events. Inventory, tools and an in-progress
installation's replacement remain intact. Ordinary physical installation restores
operation when the part fits the specification and the service is enabled. A fault
in phase one precedes a same-tick installation completion in phase two.

Automatic wear uses the dedicated `wear` PCG stream, stable machine-ID initialization,
and uniform integer intervals symmetric around the configured mean. D-77 defaults to
2592000 ticks; zero explicitly disables timers. Explicit fault disturbances do not
consume random draws or change the wear schedule. Timers continue on empty/disabled
machines. Configuration is optional so scenarios can declare their scope.

Faults do not update authority beliefs or create jobs directly. Only local stationary
observers sense the passive status light; the required part remains inspection-only
by default. Declared sensors retain their sample/delivery latency. Facility duties
then use ordinary private report goals, terminal posts, receipt, assignments, reads,
acknowledgments and work reports. Causal traces link fault events to their observations.

Failed parts reconcile by resource against initial balances and recipe transactions.
Decimal reconciliation intermediates avoid overflow from lifetime production while
physical stock remains within Int64. Registered credential cards cannot enter these
consumable machine slots. This is an explicit sink model, not a damaged-item/salvage
model; no replacement part is generated by the fault.
